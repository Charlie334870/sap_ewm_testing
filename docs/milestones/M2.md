# Milestone 2: Read-only SAP tools

The controlled tool layer between an agent and SAP, a simulated SAP system to practise on, a real
connection to SAP's public API sandbox, and a way for Claude to use the tools today.

## What was built

| Planned item (architecture document, section 13) | Result                                                                                                                                  |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| Ten tool contracts                               | Eleven read-only tools with input and output schemas (`get_storage_bin` added because SAP has a released API for it)                    |
| Tool gateway                                     | One function runs every call: project, role, environment, input schema, connection support, identity, time limit, output schema, record |
| Simulated adapter, first three scenario packs    | Simulated warehouse MUHW with a healthy baseline and three planted faults (use cases 1, 5, 9), each with a practice ticket              |
| MCP server                                       | `apps/mcp`: stdio server exposing 3 platform tools, the 11 SAP tools and an investigation prompt; committed as one bundled file         |
| Tool console in the UI                           | System page: run any tool with a generated form, see the result as an agent would, list of recent calls                                 |

Added beyond the plan, towards a real SAP connection at no cost:

| Addition                          | Why                                                                                                                                     |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| SAP API sandbox connector         | The only free way to exchange real requests with SAP software. Read-only OData client, six tool bindings, connection test.              |
| Encrypted SAP credentials         | The sandbox needs an API key. Stored with AES-256-GCM under a key outside the database.                                                 |
| Agent access tokens               | Lets Claude Desktop act as one user in one project, read-only, so the tools can be driven by an agent before the built-in agent exists. |
| Answer keys and solvability tests | Each scenario's root cause and required evidence, checked to be discoverable with the tools and unreachable from the running system.    |

## How it was checked

- **Automated tests: 141, all passing.** 58 from Milestone 1 plus 83 new: tool contracts, the
  simulator, secret encryption, the OData connector and connection test, tool execution and the
  sandbox connection through the API, access tokens, the MCP server with a real MCP client, the
  web proxy, and one test per piece of scenario evidence.
- **Isolation tests confirmed to fail** when token confinement or system-to-project scoping was
  deliberately broken. One of them did not fail at first; the test was strengthened until it did.
- **Browser walkthrough** against the production web build: register both kinds of system, create
  practice tickets, run tools including a refused one, create a token.
- **MCP end to end:** the committed bundle was started over stdio exactly as Claude Desktop starts
  it, through the web proxy to the API, and a real MCP client listed and called the tools. This
  found a real defect (the web proxy dropped the token header), which is fixed and now has a test.
- **Upgrade:** a Milestone 1 database with data was migrated to the new schema.

## Known limits

- **The sandbox connector has not exchanged a request with SAP yet.** The build environment
  cannot reach sandbox.api.sap.com. It was tested against a stand-in generated from SAP's
  published definitions. The first real call happens when the connection test is run on a machine
  with internet access. See [SAP-CONNECTION.md](../SAP-CONNECTION.md) for what is unverified.
- **Claude Desktop itself was not part of the test.** The MCP server was tested with the official
  MCP client library, not with the Claude Desktop application.
- **The Docker variant of the MCP server is untested**, like every Docker image here: Docker Hub
  is unreachable from the build environment.
- **Five tools have no real connection yet:** queues, application log, PPF, dumps, customizing.
  SAP has released no API for them. They work on the simulated system only.
- **Scenario data is illustrative.** Document types, process types, stock types and queue names
  are written in the style of an SAP standard warehouse and need review (`TODO – verify`). Log
  texts carry no SAP message numbers.
- **Three of ten use cases have a scenario.** The others follow with Milestone 5, ideally from
  real tickets.
- Tool call records are insert-only by code. They are not protected by the hash chain that
  protects the audit log.

## What you can do now

1. Update and restart: `git pull`, then `docker compose up --build`.
2. Try the tools on a simulated system ([SETUP.md](../SETUP.md), step 7).
3. Connect SAP's API sandbox and send the connection test result ([SAP-CONNECTION.md](../SAP-CONNECTION.md)).
4. Let Claude investigate the practice tickets ([CONNECT-CLAUDE.md](../CONNECT-CLAUDE.md)).
