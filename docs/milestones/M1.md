# Milestone 1: Foundation

A running, tested skeleton that every later milestone builds on. No SAP and no AI in it.

## What was built

| Planned item (architecture document, section 16)                  | Result                                                                                       |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Monorepo, linting, formatting, test runner                        | pnpm workspaces, TypeScript, ESLint, Prettier, Vitest, CI workflow                           |
| Docker Compose with PostgreSQL and pgvector, one command to start | `compose.yaml` with database, API and web                                                    |
| Schema and migrations for all tables of section 9                 | 24 tables in `packages/database`; migrations applied on API start                            |
| Login, roles, membership checks on every route                    | Cookie sessions, scrypt password hashes, three project roles plus organisation administrator |
| Projects, SAP system records, tickets                             | Create, list, view; ticket timeline, comments, status changes; ticket numbers per project    |
| Append-only audit log                                             | Written in the same transaction as each change; hash-chained; database triggers reject edits |
| UI shell with the ten sections                                    | Five working, five labelled with the milestone that delivers them                            |
| Tests for access control, isolation and audit                     | 58 automated tests                                                                           |
| Setup guide for a non-developer                                   | `docs/SETUP.md`                                                                              |

Added beyond the plan because the console is unusable without them: user management for the
organisation administrator, changing your own password, an administrator setting a new password
for a locked-out user, and an integrity check for the audit log.

## How it was checked

- **Automated tests (58, all passing)** against a real PostgreSQL 16 database:
  sign-in and sessions, the role matrix, project isolation against three kinds of outsider,
  ticket numbering under concurrent creation, audit completeness, and audit tamper detection.
  Two isolation tests were confirmed to fail when isolation was deliberately broken in the code.
- **Browser walkthrough** of the exit test in `docs/SETUP.md`, run against the production build
  of the web console, at desktop and phone width.
- **Type check, lint and formatting** pass for all packages.

## Differences from the plan

| Plan                                                      | What was done                | Why                                                                                                  |
| --------------------------------------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------- |
| `document_chunks` holds an embedding and full-text column | Table created without them   | The vector size depends on the embedding model, which is chosen by test in Milestone 4.              |
| API tests in `/tests`                                     | They live in `apps/api/test` | Tests sit beside the code they test. `/tests` is kept for scenario packs and the evaluation harness. |
| Packages for SAP tools, MCP, AI, agent, knowledge         | Not created yet              | Empty packages add noise. Each is created in the milestone that builds it.                           |

## Known limits

- **The Docker images were not built during development.** The build environment could not
  download base images from Docker Hub. The steps of both Dockerfiles were rehearsed outside
  Docker (clean install from the lockfile, API start, web production build) and the application
  was run and tested that way. The first `docker compose up --build` on a real machine is
  therefore the first true test of the images. `docs/SETUP.md` lists the likely errors.
- **The CI workflow has not run yet.** It runs for the first time when the code is pushed to GitHub.
- The API container runs TypeScript directly with `tsx`. A compiled build is a later optimisation.
- Sessions last 12 hours. There is no single sign-on and no two-factor sign-in yet.
- There is no email. An administrator creates users and passes on their first password.
- The audit hash chain detects tampering; it cannot prevent a database superuser from attempting it.
- Row-level security in PostgreSQL is not enabled yet. Isolation is enforced in the API layer and
  covered by tests; row-level security is added before a second client is onboarded.
